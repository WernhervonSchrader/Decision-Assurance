# Decision-Assurance

Decision Assurance ist der Spezialfall des Reliable Intelligence Framework in Bezug auf sichere und nachvollziehbare Entscheidungen.

## Arbeitsregeln für dieses Repository

Damit GitHub, der lokale Klon und der Cloud Code-Space immer identisch bleiben, gilt folgende Regel:

- Vor jeder Arbeit zuerst pullen:
  - `git pull origin main`
- Nach jeder Änderung committen:
  - `git add .`
  - `git commit -m "Beschreibung der Änderung"`
- Nach jedem Commit direkt pushen:
  - `git push origin main`

## Für VS Code und ChatGPT

Dieses Projekt soll immer über GitHub als Quelle der Wahrheit laufen. VS Code und ChatGPT arbeiten nur mit dem Repository, das über GitHub synchronisiert ist. Wenn Änderungen vorgenommen werden, müssen sie vor dem Weiterarbeiten eingecheckt und gepusht werden.

## Kurzregel

- Start der Arbeit: immer erst pullen
- Ende einer Änderung: immer pushen

Merksatz: "Pull before you work, push after you commit."
